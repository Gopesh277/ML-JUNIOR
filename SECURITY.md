# Security Policy

## Supported Versions

Security fixes are generally applied to actively maintained versions of ML-JUNIOR.

| Version               | Supported |
| --------------------- | --------- |
| Latest release        | ✅         |
| Older releases        | ⚠️        |
| Unmaintained releases | ❌         |

Users are encouraged to use the latest available version of ML-JUNIOR.

## Reporting a Vulnerability

If you discover a security vulnerability in ML-JUNIOR, please do not publicly disclose the vulnerability before it has been investigated.

Instead, report it privately through the security reporting functionality provided by GitHub for this repository.

If private security reporting is unavailable, contact the project maintainer privately through the contact information associated with the repository.

## What to Include

Please provide as much information as possible, including:

* Description of the vulnerability
* Affected ML-JUNIOR version
* Steps to reproduce the issue
* Potential impact
* Relevant logs or error messages
* A minimal proof of concept, when safe to provide

Please do not include passwords, API keys, tokens, private datasets, or other sensitive information in a report.

## Response

The maintainers will review valid security reports and determine the appropriate response.

Depending on the severity of the issue, the project may:

* Release a security fix.
* Release a patched version.
* Publish a security advisory.
* Update documentation.
* Request additional information from the reporter.

## Responsible Disclosure

Please allow the maintainers reasonable time to investigate and address a reported vulnerability before publicly disclosing technical details.

We appreciate responsible security research and contributions that help make ML-JUNIOR safer.
